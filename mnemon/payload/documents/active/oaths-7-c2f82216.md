# 《灰誓》长夜誓约（Oaths）机制实现与验收

时间：2026-11-05 · Godot 4.7.2.stable（`.tools/Godot.app/Contents/MacOS/Godot`）· 项目根 `/Users/liuyongze/Desktop/灰誓`
目标：增加高重玩机制吸引玩家，按《杀戮尖塔》式结构加入开局誓约、每日誓约、精英词缀、局内评分四层，并全部接入真实 UI 与存档。

## 四层机制与设计理由

| 机制 | 内容 | 为什么能留住玩家 |
| --- | --- | --- |
| 开局誓约 | 6 条，三选一，全部「恩惠 + 代价」（血誓 +1 首回合能量 / 生命 −12%；拾荒誓 战斗金币 +12 / 起始金币 −30；缄默誓 首回合多抽 1 / 禁篝火回血；猎手誓 精英奖励必出稀有 / 精英 +20% 生命；铁誓 开局 8 格挡 / 战后少回 3；余烬誓 +1 力量 / 商店 +20% 价格） | 同职业每局玩法不同，流派产生取舍 |
| 每日誓约 | 按日期派生角色 + 誓约 + 「长夜变体」（敌血 +15%、金币 +50、开场 +2 力量、生命 −15%、商店 −25%、首回合多抽），记录最佳分/尝试次数/连续天数 | 每天回来一次的理由，可比较、可连击 |
| 精英词缀 | 守夜（开局 12 格挡）、饥饿（每回合 +1 力量）、荆棘（4 反伤）、灰幕（+25% 生命），按种子确定性抽取，读档不重掷 | 精英战变成需要应对的关卡，而非同一模板 |
| 局内评分 | 层数×10 + 精英×30 + 首领×120 + 金币 + 生命×2 + 难度×100 + 胜利 500，结算进历史与每日最佳 | 给「再来一局」明确刻度 |

## 代码落点

核心新模块：`core/oath_mechanics.gd`（誓约/每日/词缀纯逻辑，含 `modifiers_for`、`value`、`offers`、`pick_affix`、`daily_key`、`daily_setup`、`apply_max_hp`）、`core/combat_flow.gd`、`core/run_flow.gd`、`core/meta_progress.gd`、`core/save_store.gd`、`core/content_db.gd`、`core/map_gen.gd`、`core/random_streams.gd`；`core/game_engine.gd` 648 行、`ui/main.gd` 4,738 行、`core/combat_flow.gd` 959 行。

誓约在战斗侧的挂点（全部走 `Oaths.value(state.modifiers, ...)`）：
- `core/combat_flow.gd:88` start_strength、`:92` start_block、`:98` enemy_hp_pct、`:143` first_turn_energy、`:175` first_turn_draw、`:907` combat_gold_flat、`:910` combat_heal、`:923` elite_reward_rare。
- `core/combat_flow.gd:106` 词缀用 `Oaths.pick_affix(seed + chapter*131 + row*17)` 抽取，`:109-111` 叠加 hp_pct / start_block / start_thorns。
- `core/meta_progress.gd:54-57` 开局写入 modifiers、max_hp、起始金币；`:76` offers；`:94-98` daily_key/daily_setup；`:128-145` 每日开局与金币修正。

UI 约定（node name 供无头测试定位）：标题页 `DailyVowButton`；角色页内联 `OathDraft` 面板（`OathCard_0/1/2` 可再点取消、`SkipOathButton`，`BeginJourney` 仍一次点击直接开局）；`menu_page = "daily"` 的 `DailyVowScreen` + `StartDailyButton`；HUD 的 `OathChip`/`DailyChip`；战斗 `EliteAffixBanner`；结算增加得分与今日最佳/连续天数。

## 存档兼容

`state` 新增 `oath`、`modifiers`、`daily`、`daily_key`、`daily_modifier`、`elite_affix`、`run_elites`、`run_bosses`、`score`；`profile.daily` 记 best/best_role/best_oath/streak/last_key/history（上限 20 条）。旧存档经 `_blank_state()` / `_new_profile()` 合并默认值，**不提升 `SAVE_VERSION`、不改 `content_version`**。
