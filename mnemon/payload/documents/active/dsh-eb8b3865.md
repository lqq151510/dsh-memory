# DSH 归档会话管理插件

## 定位与来源

源码目录：`/Users/liuyongze/plugins/dsh-archive-manager`。项目说明见 `README.md`，设计与验证计划见 `docs/superpowers/plans/2026-11-12-archive-manager.md`。

这是 Codex 风格的原生归档管理设置节，入口为 **设置 → 归档会话**。设计约束是在线使用、不退出或重启 DSH；离线方案已撤回。原生会话菜单仍负责归档，插件不另建归档标记或替换侧栏。

本文记录 2026-11-12 检查与验收时的实现，不保证未来宿主版本仍有相同能力边界。

## 原生接口与职责边界

- 纯客户端设置节；Host 入口不注册接口或模型工具。
- 使用设置槽位提供的 `useWorkspaces`、`useSessions` 快照，按原生 `archivedSessionIds` 合并标题、工作目录和更新时间。仅展示真正归档的 ID；去重，保留元数据缺失的记录，后续快照可补齐。
- 搜索标题、工作目录或会话 ID，按字面匹配而非正则；列表按更新时间稳定排序。
- 恢复调用原生 `uiWorkspace.unarchiveSession`；恢复后打开调用 `uiWorkspace.openSession`。访问控制、侧栏更新与多客户端同步继续由宿主原有机制负责，而非插件另建状态源。
- 批量恢复串行执行，每条操作前重新核对最新归档状态；失败报告详情、不自动重试、不回滚已成功项目；停止或设置面板卸载后不再启动后续操作。
- 不读取消息正文，不恢复后台 Agent，不请求模型，不增加轮询。界面使用原生主题变量，并提供中英文与窄屏布局实现。

## 永久删除：未交付的需求

在已检查的 **DSH 0.2.2-rc.2** 中，没有能够协调会话写入器、全部持久化代、附件、缓存和索引的正式在线永久删除接口。因此永久删除按钮明确禁用，并说明原因；**恢复、取消归档或隐藏都不是删除**。

插件不删除会话日志、锁文件、附件或索引，不修改主程序，也不提供“结束当前回合后直接删文件”的绕过方案。真正永久删除需等待宿主提供正式删除协议再接入。用户最初要求的彻底删除仍未实现，不能将归档管理交付称为该需求已满足。

## 安装与回滚边界

当前 profile 的安装、启停和卸载仅通过 `plugin_manager` 管理，不手动修改 profile 文件。禁用或卸载只移除管理入口，不应改变原生归档状态或历史内容。

2026-11-12 的验收证明此插件已热安装到 desktop profile，前后为同一桌面进程，未退出、重启或额外启动浏览器。这是该插件当时的验证结论，不是所有客户端插件均可免重启的通则。

## 可复现验证与证据范围

开发验证命令：

```bash
npm run build
npm run check
```

检查点中的自动测试输出为 **9 项通过、0 失败**，覆盖设置槽位注册、真实归档集合合并、缺失元数据与去重、字面搜索、稳定排序、串行恢复、逐项新鲜状态检查、部分失败、停止后续操作及删除能力禁用。

README 记录的真实原生 GUI 验收：

1. 搜索无结果、清空搜索、全选当时显示的 50 条及取消选择；仅选择未改变原有会话归档状态。
2. 新建并确认专用会话 `Non-Destructive Archive Management Acceptance Test`，完成原生归档 → 插件搜索 →「恢复所选」（1 条）。
3. 再归档该测试会话，点击标题完成「恢复并打开」；原生侧栏与当前会话正确更新。
4. 测试记录最终留在原生归档中；没有删除会话，没有改变原有用户会话的归档状态。

**未做真实环境验收：** 多条会话实际批量恢复、其他客户端同步、窄屏与深色模式。多条串行、竞态、部分失败只有自动测试依据。后续修改或宿主升级后需重新验证，不能直接沿用历史通过结论。
